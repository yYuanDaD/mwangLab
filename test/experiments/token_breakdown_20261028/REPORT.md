# 45 篇大规模运行：token 花在哪里

数据来自你电脑上 45 个单篇子任务的会话记录（每篇一个），一共 2834 条工具调用和思考。只统计了 token 数，没有读工具输出的正文。

## 结论

每篇平均最终上下文 17.7 万 token，33 轮。其中只有大约 19% 用在真正需要模型判断的地方：读论文、看数据、思考。41% 用在"学怎么做"，以及写、跑流程脚本上。这部分每篇的内容都差不多，正是代码固化能省掉的。

| 类别 | 每篇 token | 占比 | 固化后 |
|---|---|---|---|
| 固定开销：系统提示词、工具定义、任务说明（第 1 轮就有） | 69.5k | 39% | 不变，但轮数少了，重复读的次数也少 |
| 学怎么做：读 skill 文档 | 26.5k | 15% | 去掉 |
| 学怎么做：读库代码（native.py、suitability.py、joint_contrasts.py 等） | 12.2k | 7% | 去掉 |
| 学怎么做：翻之前论文的脚本和 PROBLEMS.md 当模板 | 7.7k | 4% | 去掉 |
| 写流程脚本（gates、decisions、execute、enrich 等） | 10.0k | 6% | 只剩写决策 JSON |
| 跑脚本、零散 shell、回读被截断的长输出 | 16.6k | 9% | 大部分去掉 |
| 科学判断：读论文 | 10.8k | 6% | 保留 |
| 科学判断：查看 metadata 和数据文件 | 10.4k | 6% | 保留 |
| 思考和文字 | 11.5k | 7% | 保留一部分 |
| 最终汇报 | 1.0k | 1% | 保留 |

明细见 `summary_by_category.csv`。

- **skill 文档每篇都从头读一遍。** 45 篇里，每篇都读了 `native-execution.md` 和 `decision-contract.md`。36 篇又读了 `paper-reconstruction.md`、`matrix-method-policy.md` 和 `decision-gates.md`。
- **库代码也是每篇都翻。** `tools/native.py` 被翻了 96 次，`tools/suitability.py` 55 次。模型是在现查函数怎么调用。
- **gates 脚本最贵。** 它是最长的一类脚本，单个约 18 KB。所有写脚本的调用一共产出 32.8 万个输出 token，gates 占了将近一半。决策记录现在是写成 Python 代码的，改成 JSON 以后这部分会小很多。
- **轮数会放大成本。** 那 7 万 token 的固定开销每一轮都要重读一次，占了全部重复读取量的 49%。所以轮数从 33 降下来，省得比上下文变小还多。

## 固化能省多少

按两种情况估算：只保留固定开销、读论文、看数据、写决策，以及这些轮次里的思考；或者再额外保留写 gates 脚本和跑脚本的轮次。按 API 价格折算（缓存读 0.1 倍，缓存写 1.25 倍，输出 5 倍）：

| | 现在 | 固化后（估算） |
|---|---|---|
| 每篇最终上下文 | 17.7 万 | 10 万到 11 万 |
| 每篇轮数 | 33 | 10 到 13 |
| 折算成本 | 100% | 30% 到 40% |

这是上限。它假设固定脚本一次就能跑通，实际还会有失败重试，所以按"大约省一半"来预期比较稳妥。

## 建议的固化方案

1. **决策 JSON（case spec）。** 模型只填这些内容：论文证据的位置、样本对齐规则（就是 `derive_columns` 的 aliases、patterns、recode）、设计公式、比较组、方法、阈值，以及论文里报告的数字。在现有 `decision_contract` 的基础上加一个 schema。
2. **一个固定的执行器。** 它读入 case spec，依次完成下载、对齐、适用性检查、DE、阈值、富集、和论文对比，最后写入 `RunRecorder` 记录。失败时返回结构化的错误，让模型改 JSON 再跑，而不是让模型自己去改代码。
3. **skill 改成短版本。** 只讲怎么填 case spec，以及每个字段该怎么判断。`native-execution.md` 和库代码的细节就不用模型去读了。
4. **另外一个便宜的改进。** 7 万 token 的固定开销大部分来自 Claude Code 本身：系统提示词和所有工具的定义，可能还包括你电脑上接的 MCP 工具。跑单篇的时候只给它 Bash、Read、Write，可能还能再省一块。这一点还没验证。

## 数据说明

- 最早跑的 11 篇（10-19、10-20 那批）几乎没有记录到输出 token，每篇只有约 600，后面每篇约 2.9 万。所以写脚本和思考的占比被低估了一些，结论方向不受影响。
- 同一轮里有多个工具调用时，新增的 token 按各自结果的长度分摊。
- 原始 CSV（`calls.csv`、`transcripts.csv`）里有命令文本和路径，所以只留在你电脑上，没有提交。重新统计的方法：先运行 `extract_usage.py`，再运行 `classify.py`。
