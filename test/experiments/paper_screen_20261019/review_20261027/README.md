# 筛选器分层复核（2026-10-27）

用当前筛选器（2068c62）从 10-19 的缓存重筛 1000 篇，再按每层、每个子原因抽样 58 篇（种子 20261027）逐篇核对。没有调用任何付费 API。

- `review_sheet.xlsx`：复核表。“复核”页是 58 篇抽样，“GEO反查可补回”页是 45 篇被提前排除、但 GEO 自己把 RNA-seq 系列挂在其 PMID 下的文章。黄色两列留给人工填写。
- `screen.csv` / `screen_summary.md`：重筛结果（42 篇可分析，17 篇待看，941 篇排除）。
- `geo_by_pmid.csv`：每篇有 PMID 的文章，GEO 挂在它名下的系列（elink pubmed→gds）。
- `whatif_geolink.csv`：把这些系列当作自有数据，跑数据层的结果。
- `fulltext/`（不提交，只在本机）：每篇已缓存的全文 .md，表里“全文（本地）”列链接到这里；表格要在本目录打开链接才有效。
- `scripts/`：上述各步的脚本；`judgments.py` 是 58 篇的人工判断。

## 结果

58 篇抽样里，我判断错 9 篇、存疑 3 篇；另有 9 篇按现规则正确，但取决于政策（芯片、只有 FPKM/log 值、只有 SRA、物种）。

|---|---|---|
| 1. 自有数据判成引用：数据声明里的 “publicly available” 被当成重用 | #19 GSE205676、#21 GSE242861 | “重用公共 GSE” 46 篇中 23 篇，GEO 把 RNA-seq 系列挂在本文 PMID 下 |
| 2. 不用 GEO 自己的 PMID→GSE 链接：正文没写编号、或没取到全文就排除 | #43 GSE235174、#22 GSE222329 | 无全文 198 篇中 27 篇有 GEO 挂的 RNA-seq |

| 4. 取值检查：整数为主或估计计数的文件，因处理说明里写了 FPKM/TPKM 而判 normalized_only | #43 GSE235174、GSE163356 | |
| 5. 分组规则要求所有组都 ≥3，被无关小组拖累 | #49 GSE297515（SED 6 对 AEX 3） | 2 个系列 |

只修第 1、2 条（用 GEO 的 PMID 链接认自有数据）：被提前排除的文章里，有 27 篇标题有运动词、数据层判可分析，另 6 篇待看（见第二页）。可分析会从 42 篇增加到约 69 篇。

前几层的大头（无全文、非运动主题、无自有数据里的普通情况）抽到的都判得对：多是综述、qPCR、生理测定、荟萃分析，或与运动无关的 GEO 关联文章。

注意：GEO 的 PMID 链接不全是自有数据。#28 的 GSE163356 也挂在本文下，但正文写明是重用的公开数据，GEO 还挂着更早的 PMID。补回规则应只认“本文是 GEO 挂的第一篇”或“GEO 标题与论文标题相同”的系列；第二页 45 篇都满足这一条。

## 修改筛选器后重筛（2026-10-28）

按会议要求第 1、4、7 条和上面的修复改了 `tools/paper_screen.py`（单元测试 30/30）。从缓存重筛 1000 篇，结果在 `rescreen_fixed/`：

| | 修改前 | 修改后 |
|---|---:|---:|
| 可分析 | 42 | 124（走计数 84，走 limma 37，两种都有 3） |
| 待看 | 17 | 14 |
| 排除 | 941 | 862 |

新增的 83 篇来自：自有数据改用 GEO 的 PMID 链接或数据声明措辞 35 篇，TPM/FPKM 改走 limma 28 篇，无全文但 GEO 挂了数据 11 篇，分组、取值和文件识别 9 篇。少了 1 篇（GSE151066 现在被两篇文章认领，转为待看）。

每篇新增三列：`route`（counts / limma）、`missing`（缺什么）、`flags`（性别组成：全男 19、全女 7、混合 13、未知 85；按性别拆分后不足 3 的组；多余的小组；未标注样本）。

新暴露的问题：124 篇里有 61 篇（原来 42 篇里就有 18 篇），筛选器选中的 GEO 分组列里没有运动相关的组名。其中一部分是前后或时间点设计，一部分是运动对比在另一列，还有一部分根本不是运动研究（念珠菌、外泌 RNA 图谱、微针等）。以前这些被数据层的漏判掩盖了。下一步应在 GEO 样本信息的所有列里找运动对照，找不到就标记或排除。
