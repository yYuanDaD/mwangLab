# HANDBACK: GSE235174 / PMC10262399 (COPD, 12-week personalized aerobic training, pilot)

## What ran
- Route: case spec (`case_spec.json`, generated by `make_case_spec.py`), `python -m tools.case_runner execute`. Validator: 36 records, 0 errors. Run status: completed.
- Design: 4 male COPD patients, peripheral-blood leukocytes, pre (bPR_k, GEO "NC") vs post 12-week aerobic training (aPR_k). Contrast `time_post_vs_pre`, reference = pre.
- Matrix: `GSE235174_counts_allsamples.txt.gz` holds three tables pasted side by side (mRNA HTSeq counts | lncRNA estimated counts + Chrom | circRNA CIRI junction counts). `prep_split_blocks.py` split it into `prep/GSE235174_{mRNA,lncRNA,circRNA}_counts.csv` (2 duplicated mRNA symbols summed). One case per RNA class.
- Per case: primary = unpaired DESeq2 `~ time` (paper used DESeq 2012, two-group, no pairing stated); sensitivity = DESeq2 `~ subject + time` (pairing aPR_k/bPR_k inferred from sample names only).
- Threshold: paper's own rule, raw p < 0.05 and |log2FC| >= 1 (S3.2.p1, S4.p2; FIG2), source `paper_on_deviation_route`. Audit: BH padj < 0.05.
- Enrichment (mRNA only): ORA up/down not run (0 genes pass the padj-based ORA input, see problems); Hallmark GSEA completed.

## Deviations
- DESeq (2012) -> DESeq2 (pydeseq2 Wald), declared; DESeq2 dispersion shrinkage and Cook's filtering differ from DESeq 2012.
- lncRNA block treated as estimated counts (non-integer, e.g. 5745.37) and rounded for DESeq2; medium confidence on its scale.
- circRNA: our 18 vs paper 2064 is not reconciled. The paper says circRNA expression was computed as RPM; the vendor's DESeq run may have used different input or filtering. Sparse junction counts (column sums 18k-71k) give little power in DESeq2.
- No FDR in any result (n = 4/arm); the paper's raw-p rule is used as the applied threshold, so most "DEGs" are expected under the null. Pairing in the sensitivity run is inferred, not documented.

## Tool problems
1. `tools/case_runner.py:768-771`: when the applied threshold uses raw p, ORA input is silently switched to padj < 0.05 with the applied FC cutoff, so ORA on the paper's DEG list (raw p) is impossible; here it gave 0 input genes and ORA up/down were recorded not_run.
2. `tools/deseq2_tools.py:160`: `refit_cooks=True` is hard-coded with no option; with < 7 replicates pydeseq2 sets p = NaN for Cook's outliers, dropping key paper genes (ELANE, MPO, AZU1, DEFA4, PLCB4) from the unpaired comparison. No way to reproduce DESeq-2012-like behaviour.
3. `covariate_columns` must be a comma-separated string; passing a JSON list (natural in the spec) fails at execution with "'list' object has no attribute 'strip'" (`tools/deseq2_tools.py:105`) instead of a spec_error.
4. Relative `inputs.matrix` paths resolve against `data_root`, not the repo root, so run-dir prep outputs need absolute paths (first attempt in `_previous/` failed with FileNotFoundError).
5. `inspect` reported the multi-block counts file as one 24-sample "linear_normalized or estimated_counts" matrix with 32k duplicated IDs; it does not detect side-by-side blocks with repeated sample headers.
