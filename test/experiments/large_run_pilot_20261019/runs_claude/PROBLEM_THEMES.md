## One-off problems that look serious (silent wrong results)

- **PMID41314005 (GSE308674)**: the deposited counts file is corrupt for 6 long genes (annotation text cut at 32,759 characters and continued on extra rows: 1080 NaN counts, 18 duplicated IDs); no tool check. Repaired by hand.
- **PMID40295575 (GSE283250)**: `geo_tar.py:108-118` keyed tar members on the first column (gene symbol) and kept the first duplicate, silently dropping 10,116 of 33,299 transcript rows.
- **PMID34943951 (GSE188236)**: `geo_tar.py:118` outer-joined long-RNA (60,666 genes) and small-RNA (602 IDs) files and zero-filled the gaps, with no assay check or warning.
- **PMID40577041 (GSE267763)**: voom executor has no TMM, so p-values piled near 1 (0 of 7,210 genes at p < 0.05 vs the paper's 365) and `deg_sanity` still said ok. The same gap appears in PMID33486778, PMID35025912, 87d00364, PMID35850762 and PMID35482926.
- **PMID42594877 (GSE308252)**: numeric subject IDs in `covariate_columns` were fitted as one continuous slope, silently unpairing the design (1,105 vs 2,819 DEGs). Patched in the run; a scan of earlier runs found no other case. The same pattern is still reported for `run_joint_limma` (PMID38151020, `joint_contrasts.py:166`).
- **PMID35198907 / PMID31350552**: edgeR QL wrote the unsigned F statistic as `stat`, so GSEA ranked on an unsigned value (patched at row 103).
- **PMID42711121, PMID42241015, 2dc6a814**: ORA with zero input genes was recorded `failed`, and the `up` status key was overwritten by `down` (patched before row 18 resumed).
- **PMID38232699 (GSE214282)**: `deseq2_tools.py:180` always shrinks `log2FoldChange`, giving about 40% tied GSEA ranks (similar 19-27% ties in PMID42272974, PMID33661096, PMID29610328, PMID39523700). Open.
- **PMID34252634**: no count-dispersion check, so DESeq2 on normalized values passed as ok; the case also records `log2(x+1)` despite pseudocount 0.5 (`case_runner.py:654`). Open.
- **PMID33257951 (GSE153100)**: the xlsx-to-csv conversion wrote Excel-date gene symbols so that MARCH1/MARC1 collide and the duplicate-gene collapse would sum them. Row 74 added only a report flag, not a fix to the collapse.
- **PMID41326383, PMID36939205, f7900835**: `case_runner.py:749,871` keys multi-follow-up paired_change tables by contrast name only, so h3 is overwritten by h24. Open.
- **PMID40693573 (GSE279359)**: header one field shorter than its rows, so `native.read_table` reads annotation columns as numbers with no warning (`native.py:199-201`). Open.
- **PMID35689600**: a second header row (fastq names) kept as data; inspect shows integer_fraction 1.0 without flagging it. Open.
- **PMID39000297 (GSE232510)**: header-less HTSeq files lost their first gene per sample and kept `__no_feature` rows as genes (patched mid-run); `check_sex` passed with no markers (patched).
- **9eef7b26**: `limma_tools.py:106-107` silently drops zero-variance genes (26,111 to 21,248) with no entry in the method record. Open.
- **PMID39232281 (GSE243060)**: `joint_contrasts` silently skipped a planned contrast with n = 2 (patched via `include=[...]`); `check_covariance` failed whole tissues on a batch-like name aligned with sex (not fixed).
- **PMID40639377, PMID41933175, PMID42666019**: "exercise mediator" series (in-vitro, no exercise arm) were run, while GSE188236 and GSE245048 were refused in the same situation. Inconsistent decisions; needs a rule rather than a tool fix.
