# Tool patches during the 211-paper run

A tool is patched only after the same problem appears in 2 or more papers.

| After paper | Problem | Papers | Patch |
|---|---|---|---|
| 3 | Paper-gene check finds no genes when the DEG table is indexed by Ensembl ID (`_gene_lookup`, `tools/case_runner.py`) | PMID39393048, PMID42711121 | Map the Ensembl index to symbols with `enrichment_tools._query_symbols` (organism from the design gate) when no paper gene matches directly |
| 6 | `inspect` profiles the `.xlsx` as text (UnicodeDecodeError) and a spreadsheet title row breaks the header (`native.read_table`, `case_runner._candidate_files`) | PMID42711121, PMID37365374, PMID35133080 | `read_table` reads `.xlsx` with `read_excel` and takes the first row that fills half the columns as the header; inspect skips an `.xlsx` whose converted `.csv` is present |
| 9 | A planned non-reference pair in the paper's direction (e.g. `grp_KOEx_vs_KOSed`) is missing because pairs are enumerated in one fixed direction, so the joint model cannot run it (`suitability.enumerate_comparisons`) | PMID40623475, PMID40993371 | `suitability.add_reversed_planned` adds the reverse of a simple comparison when a planned name asks for it |
| 7 | `inspect` downloaded an 11.6 GB bigWig `_RAW.tar` and left it truncated; skip-if-exists then treats the partial file as complete (`geo_tools.download_supplementary_files`). Patched after one paper because a few more of these would fill the disk (66 GB free) | 4a5659c6 (GSE129694) | Files over `BIOAGENT_MAX_SUPPL_GB` (default 3) are skipped and listed; downloads go to `.part` and are renamed when complete. The truncated tar was deleted |
| 18 | The validator called a rule with no effect cutoff a threshold mismatch when only `effect_metric` differed (null vs `log2FoldChange`), so two finished runs came out INVALID at `case.finish` (`decision_contract._same_threshold`) | 2dc6a814 (GSE195585), PMID34142717 | `effect_metric` is ignored when neither rule has an effect cutoff; both runs re-validated VALID |
| 18 (before resuming) | ORA with no input gene was recorded as `failed`, and its status key dropped the direction so `up` was overwritten by `down` (`case_runner._enrich`) | 42711121, PMID42241015, 2dc6a814 | ORA whose input threshold passes 0 genes is recorded `not_run` with `reason_not_run`; status keys keep the direction in every branch |
| 22 | `alignment.key_patterns` / `patterns` take one regex group only, so a key like `Sed_1` cannot be built from `Sed 1` without a prep script (`native.derive_columns`) | PMID40623475, PMID31700184, 4671b217 | Several regex groups are joined with `_`; the case-spec reference says so |
| 22 | Input paths: a prepared matrix in the run directory was rewritten to `data_root/<path>`, and `raw_tar` looked for the tar beside a prepared metadata copy instead of the series folder (`case_runner.Spec._resolve_inputs`, `_matrix_input`) | 4671b217, PMID42310491 | `data_root` is put in front only when the path does not exist as given; `inputs.series_dir` (default `data_root/<accession>`) is where `raw_tar` looks when the metadata folder has no tar |
| 23 | `complete_pairs` crashed with TypeError: the runner passed keyword-only arguments of `native.complete_pairs_subset` positionally (`case_runner._prepare`) | PMID39393048, PMID38232699 | Call with keywords; checked on a small paired table |
| 23 (before row 24) | `covariate_columns` given as a list crashed DESeq2 on `.strip()` (`deseq2_tools.run_deseq2_analysis`) | PMID28273480, 917d2888 | A list is joined to the comma string the tool expects |
| 32 | Thresholds could not express a paper's mixed rule ("P < 0.05 and \|log2FC\| >= 0.5") or an asymmetric fold change ("FC > 1.2 or < 0.83"); agents recomputed counts post hoc (`native.apply_threshold`) | 0f65e49e, PMID41835150, PMID39730655 | `effect_inclusive` (separate from the p cutoff's `inclusive`) and `effect_cutoff_down`; the validator compares `effect_cutoff_down`; documented in the case-spec reference |
| 31 | `inspect` suggested no alignment key when the matrix covers only part of the series (one matrix per sex or per experiment), because the contained-name key needed half of all metadata rows (`case_runner._contained_keys`) | PMID42356398, 0efeba509681ac38012819324e7f12d6e307a4fe | Coverage is judged against the smaller of the metadata and the matrix |
| 36 | The run's headline `n_deg` took the first result table of a joint model (file order), and was blank when no execution had role `primary` (`case_runner._finish`) | PMID40623475, PMID34142717, PMID41118251 | Uses the primary execution (or the first execution) and, within a joint model, the first planned comparison |
| 39 | No low-count gene filter in the runner, so papers that used filterByExpr or a CPM cut needed prep scripts or got different gene sets | PMID35133080, PMID31700184, PMID42019489, PMID41911459, PMID41076654 | Execution option `filter_low_counts` ({min_cpm, min_samples}), applied after subset/pairs and before the transform; genes before/kept recorded; documented in the case-spec reference |
| 42 | When the paper's DEG rule uses raw p, ORA silently switched to padj < 0.05 and often got few or no genes (`case_runner._enrich`) | 0f65e49e563e3417d3cee92f75eba6244b276201, 917d28883ad57a66410a4fc20fd7e6dccd3695c6, PMID41027539 | `run_enrichment_analysis` takes `p_column="pvalue"`; the runner gives ORA the applied rule itself |
| 45 | (a) `filter_low_counts` (added after row 39) computed CPM on the case's log-transformed matrix; (b) inspect counted numeric annotation columns (Start/End/Length, DESeq2 result columns) as samples (`native.profile_matrix`) | (a) PMID41828598; (b) PMID41118251, PMID41831133, PMID41828598 | (a) The filter starts from the aligned counts and then applies the execution's or case's transform; (b) inspect drops columns with known annotation names when samples remain |
| 35 | `native.feature_id_report` read tab-separated files as one comma column, so IDs came out as "other" and inspect gave no ID type | PMID38697122, PMID42003465 | Sniffs the separator; reads `.xlsx` through `read_table` |
| 53 | `filter_low_counts` had only a CPM rule; papers that filter on raw counts (count >= 10 in n samples, mean count >= 10) needed prep scripts | PMID38766755, PMID40695537 | Adds `{min_count, min_samples}` and `{min_mean_count}`; documented in the case-spec reference |
| 55 | The validator rejected `paper_threshold: null` when the paper states no rule, though the skill then says to use `workflow_default` (`decision_contract.validate_record`) | PMID41911459, d446594d1ade71b3541cb0f6a971599e29ccdf5a | Null is accepted at paper_reconstruction, and at the threshold gate when `threshold_source` is `workflow_default` |
| 58 | When the alignment key sits inside the matrix column names (`PBS1_Count`, `Sample_3_counts`), `key_patterns` could only rewrite the metadata, so prep rename scripts were needed | PMID41076654, PMID41383117, PMID41078024 | Alignment option `matrix_column_pattern` (regex on the matrix column names; groups joined with `_`; distinct keys required); documented in the case-spec reference |
| 65 | `filter_low_counts` worked only on raw counts, so papers that filter FPKM/TPM (e.g. FPKM >= 1 in n samples) needed a prep matrix | 86991572b4ea250a7e68eadebb3fa005f4fe2282, b39292ba0ee11c97d2e351716ebbb6029eeee400 | Adds `{min_value, min_samples}` on the deposited values; documented in the case-spec reference |
| 66 | `_RAW.tar` members from RSEM (`*.genes.results`) and Salmon/DRAGEN (`quant.genes.sf`) were ignored, so the tar merge found no samples and agents wrote prep scripts (`geo_tar.unpack_and_merge_geo_tar`) | PMID41911459, PMID41126185 | Those extensions are read; `choose_count_column` picks `expected_count` / `NumReads` by header |
| 69 | Multi-group key patterns (patch after row 22) failed on rows where an optional group did not match | PMID38576560 (follow-up to the row 22 patch) | Unmatched optional groups are skipped when joining |
| 67–68 | `gene_chr` and similar numeric annotation columns were still counted as samples | PMID37872294 (follow-up to the row 45 patch) | Added to the annotation-name list |
| 74 | Excel-mangled gene IDs (`1-Mar`, `2-Sep`) collide as duplicates and inspect said nothing; inspect also gave no feature ID type | b39292ba0ee11c97d2e351716ebbb6029eeee400, PMID36839405 (ID type: PMID42003465, PMID38697122) | `feature_id_report` lists `excel_date_ids`; inspect reports `feature_id_type` and any `excel_date_ids` |
