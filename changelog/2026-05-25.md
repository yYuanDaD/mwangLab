## Changes

### 1. Agent A MVP 闭环(prompt-driven 路径)

不写硬编码 orchestrator 函数,而是把 7 步工作流写进 `main.py` 的系统提示。LLM 自己按指令链调用工具,符合 ReAct loop 设计哲学,失败也容易调:

```
PAPER-FIRST CURATION WORKFLOW (Agent A):
1. search_papers(keyword) → 候选 CSV
2. fetch_paper_text(pmcid=..., pdf_url=...) → 全文 + 提取的 accession + snippet
3. 决定哪个 accession 是 OWN data vs cited(读 snippet:"deposited" vs "downloaded from")
4. run_batch_geo_pipeline([chosen_gse], ...) → DESeq2 + GSEA
5. extract_sea_cdm_conditions(paper_text, study_id=chosen_gse) → 结构化 study/assay info
6. assemble_agent_a_record(...) → output/agentA/{PMCID}.json
7. 中文简短回复
```

### 2. `fetch_paper_text` 改 Europe PMC 优先

**触发:** 原 PDF-only 路径在 bioRxiv/MDPI/Wiley 上常被 Cloudflare 403(它们看 User-Agent / JS execution / TLS fingerprint)。

**修改:**
- 工具签名加 `pmcid=""` 参数
- 有 pmcid 就先拉 `https://www.ebi.ac.uk/europepmc/webservices/rest/{PMCID}/fullTextXML` —— 无 auth、几乎不 403、含 Data Availability 段(对找 GEO accession 是金矿)
- JATS XML 用 `xml.etree.ElementTree.itertext()` 解析成纯文本
- 没 pmcid 才退回 PDF 路径
- 加 `_normalize_pmcid()` 处理 S2 返回的裸数字 / pandas 误读成 float / `PMC` 前缀缺失等等

**Smoke test 验证**(`test/smoke/smoke_test_paper_discovery.py`):19/30 候选有 PMCID,Europe PMC 全部返回成功,GSE 命中率 ~8/12。

### 3. 新工具 `assemble_agent_a_record`(~190 行)

`tools/paper_tools.py` 加这个工具,作为 **Agent A 的最终交付步骤**。

**它干什么:** 读盘上**所有**已存在的工件 —— paper 文本 / cohort summary.csv / per-study decisions.json / study_seacdm.json —— 汇总成单文件 `output/agentA/{PMCID}.json`。

**交付物结构(v0):**
```json
{
  "version": "v0 — subset of SEA-CDM ...",
  "paper": { paperId, title, year, pmcid, pmid, doi },
  "organism": "...",
  "data_discovery": {
    "chosen_gse": "...",
    "chosen_reason": "agent 的说法",
    "chosen_snippet_verified": "工具从 paper text 重新派生的 snippet,验证 agent 没瞎说",
    "rejected_gses": [{ gse, reason, snippet_verified }]
  },
  "study_extracted": { 从 extract_sea_cdm_conditions 来 },
  "secondary_analysis": { status, n_deg, design, LLM-A reasoning, deg_csv, ... },
  "provenance": { 6 个文件路径 },
  "issues": [ fail-loud 列表 ]
}
```

**关键设计:fabrication 防线**。`chosen_snippet_verified` 字段是工具从 saved paper text 现场重新派生的 ——
**如果 `chosen_gse` 不在 paper text 里字面出现,工具会在 `issues` 里加 `CRITICAL` 标记**。
这条防线后来在第 4 节救了场。

### 4. 4 个真 bug 抓出 + 修复

工作日里跑了 2 次完整 live agent,暴露并修了 4 个 bug。

#### Bug A:S2 限流时 agent 编造 PMCID
- **症状**:keyword 跑里 S2 把这个 IP 节流(我自己测试用量大),`search_papers` 3 次 guarded 调用全 429。Agent 没按提示停下,反而 fallback 到 `search_geo_studies` → **从 GSE 编号"捏造"PMCID**(GSE214544 → PMC11214544),churn 到 recursion_limit=25
- **修复**:
  - System prompt **GUARDRAILS** 段:pmcid/pdf_url 只能用 search_papers 输出原值,不许构造;search_papers 限速时报告并停止,不许换源
  - `recursion_limit` 25 → 50(给合法长链一点余地)
  - `search_papers` 内置 4 次 429 backoff(20/40/60s)
- 用户后来提供了 S2 API key,加进 `.env`,从根上解决限速问题

#### Bug B:LLM-A 把自己的对比发现丢了
- **症状**:`validate_contrast_with_llm` 在 Python 启发式找不到对比时返回 `is_valid=True` 但 override triple 全空。Batch_tools 把它当 "confirm 无对比" → DESeq2 跳过(status=`preprocess_ok_no_design`)。但翻 LLM reasoning 才发现:**它其实清楚识别了 GSE279359 的 pre-exercise vs immediately-post 对比,只是没填进 triple**
- **修复**两处:
  - `tools/llm_helpers.py` —— prompt + Pydantic schema 重写:`is_valid=True` **仅用于** confirm Python 已选的对比;若 Python 没选,LLM 必须 *propose*(填三元组)
  - `tools/batch_tools.py` —— LLM 三元组只要填齐就采纳,无论 is_valid 标签如何;新增决策 verb `"proposed"`(区别于原 `"confirm"` / `"override"` / `"refuse"`)
- **验证:** GSE279359 重跑 → DESeq2 跑通(pre-exercise vs immediately-post)→ DEG 产出

#### Bug C:GSEA 静默"成功"
- **症状**:GSE279359 是 TALON long-read 输出,gene ID 是数字而非 symbol,Hallmark gmt 全 miss → GSEA **实际报错** `LookupError: No gene sets passed through filtering condition`。但 batch_tools 还是标 `deg_gsea_ok`,完全违反"大声 fail"原则
- **修复**:`batch_tools.py` 检测 `"gsea analysis failed" in gsea_msg.lower()` → `status="deg_ok_gsea_failed"` + 写 failures.log + decisions.json 加 `gsea: failed` 决策记录
- 同时把"非 symbol gene ID"列入 README §Known Limitations #5(GSEA + sex-check 都依赖 symbol)

#### Bug D:Agent 从训练记忆里编造 GSE
- **症状**:keyword 跑一次,3 个候选论文 fetch 完都没有 GSE 在文本里。Agent **从训练记忆里捏造了 `GSE166059`**(真存在,但和这篇论文无关 —— 是个 MKL1/乳腺癌研究)并真跑了 batch pipeline。`assemble_agent_a_record` 当时不查就过,issues=[],**这是最危险的失败模式 —— 假阳性看起来像真阳性**
- **修复**两层防御:
  - `assemble_agent_a_record` 从 saved paper text 重新派生 snippet,如果 `chosen_gse` 不在 text 里字面出现 → `issues.append("CRITICAL: chosen_gse '{X}' does NOT appear in paper text")`,报告里 critical 与 informational 分开列
  - system prompt GUARDRAILS 段加硬规则:`chosen_gse` 必须字面出现在 fetch 输出;若 2-3 候选都无 GSE → honest stop with `chosen_gse=""`,不许换源/捏造
- **从此再没出现假 GSE**

### 5. SEA-CDM schema reality 浮出水面
