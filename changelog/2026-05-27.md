### 2. 新工具:`tools/limma_tools.py::run_limma_analysis`

- **后端**:`inmoose.limma`(纯 Python 移植 R/Bioconductor limma,**无 R 依赖**)
- **签名**:`run_limma_analysis(normalized_csv, metadata_csv, design_column, control_group, treatment_group, output_dir)` —— 与 `run_deseq2_analysis` 平行,只是改名 `counts_csv → normalized_csv` 强调输入须 log-scale
- **流程**:读 → 全 NaN 列预过滤(annotation drop)→ `align_samples_with_llm_fallback` → 过滤低 NA/零方差 features → patsy `dmatrix` 建 design → `lmFit` + `eBayes` + `topTable` → 重命名 `adj_pvalue → padj` → 输出 DEG CSV
- **DEG CSV 列同构 DESeq2**:`log2FoldChange` / `lfcSE` / `stat` / `pvalue` / `padj` —— `enrichment_tools` 和 GSEA 不改一行直接消化
- **注册进 `main.py`**:工具数 19 → 20,系统提示新增 "DIFFERENTIAL EXPRESSION TOOL CHOICE" 段帮 agent 选 DESeq2 vs limma
- **smoke test**(`test/smoke/smoke_test_limma.py`):GSE266241 normalized 矩阵 33210 features × 6 samples,top-100 padj 与 DESeq2 在同一对比上 **重叠 50/100**(两种不同尺度统计模型的强一致)

**踩到的坑(已记入 CLAUDE.md):** `patsy.dmatrix(formula, data, return_type='dataframe')` 在 inmoose 里会丢列名 —— inmoose 转 `patsy.DesignMatrix(design)` 时不读 `design_info.column_names`,coef 全变 `column0/column1`。改用 `dmatrix(formula, data)` 默认返回真 `DesignMatrix` 即可。

### 3. `batch_tools.py` 按矩阵类型分流

- **`_find_raw_counts_file` → 重写为 `_find_expression_file`** —— 接受 `raw_counts | log_transformed | fpkm_or_tpm`(raw_counts 仍优先,有 raw 就用 DESeq2)
- **新增 `_log2_transform_matrix(path)`** —— 对 FPKM/TPM 写出 `<base>_log2.csv` 兄弟文件(只 log 数值列,保留 annotation)
- **per-study 分流**:
  - `raw_counts` → preprocess_counts + DESeq2(原路径)
  - `log_transformed` → skip preprocess + limma 直接吃
  - `fpkm_or_tpm` → log2 变换 + limma
- **`preprocess_counts` 对非 raw 跳过** —— CPM 归一化只对 raw 有意义,对 FPKM/TPM 是双归一化、对 log 数据更荒谬
- **`summary.csv` 新增 2 列**:`matrix_type` + `da_method`

### 6. Bug 修复

#### Bug A: LLM-B 阈值被结构列稀释(**已修**)
- **症状**:GSE317978 expression 文件 13 列 = 1 annotation + 6 samples + 6 derived stats(`diffexp_log2fc_*`)。LLM-B 正确映射 6 个样本,拒绝其余 7 个非样本列。但 `align_samples_with_llm_fallback` 阈值 `6 / 13 ≈ 0.46 < 0.5` → 整个 mapping 被丢
- **修复**:`limma_tools.py` 加 stats_tools 同样的"全 NaN 列预过滤",13 → 12 列后通过(`6 ≥ 6.0`)
- **遗留**:这只是 patch。根因是 wrapper 分母用 `len(counts_cols)` 而不是"LLM 提议的样本数"。记入 README §Known Limitations #7

#### Bug B: pandas API 不兼容
- `pd.read_csv(..., engine="python", low_memory=False)` 报 `ValueError: The 'low_memory' option is not supported with the 'python' engine`
- 修复:在 `_log2_transform_matrix` 删 `low_memory=False`
