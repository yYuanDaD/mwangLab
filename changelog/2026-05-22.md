## Changes

### 1. E3 — 性别推断 QC

新增 `tools/stats_tools.py::infer_sex_from_expression`:

- **方法**:看 6 个性别 marker 基因在每个样本的表达水平,投票产出 sex call(`male` / `female` / `unknown`)
  - Y 染色体 markers:`Ddx3y` / `Uty` / `Eif2s3y` / `Kdm5d` / `Rps4y1`
  - X 染色体 marker:`Xist`(female 高表达,male 低/不表达)
- **交叉验证**:与 metadata 里 `characteristics_ch1.*.sex` 或同义列对比,产出 mismatch 列表
- **失败模式 fail-loud**:counts 矩阵用非 symbol ID(e.g. Ensembl 数字)时返回 `no_crosscheck` 并说明原因 —— 不是悄悄返回 unknown 蒙混过去

**为什么需要这个:** GEO 样本元数据自报性别经常有错(贴错样本管、表格错位)。Sex check 是 MoTrPAC 的标准 QC 步骤,直接对数据完整性做体外验证;mismatch 是研究下游分析需要警惕的信号。

### 2. E4 — 结构化决策日志

新增 `tools/batch_tools.py::_DecisionLog` 类 + `_run_sex_check` helper:

- 每个 batch study 写 `output/cohort_{label}/{accession}/decisions.json`
- 记录每个决策点的 step / decision / reason / details,JSON 数组形式
- 步骤覆盖:`download` / `counts_detection` / `preprocess_qc` / `sex_check` / `auto_design_python` / `llm_contrast_validation`(含完整 LLM reasoning 文本) / `deseq2` / `gsea` / `exception` + `final_status`
- 与 `workflow.log`(全 stdout/stderr 流)和 `summary.csv`(每 study 一行)互补,形成三层 provenance:**机器可读决策树 + 自由文本流 + 表格汇总**

E3 sex check 同时接进 batch loop,`summary.csv` 新增 `sex_mismatch` 列(整数,等于不匹配的样本数;0 表示全通过)。

**为什么需要这个:** 之前要回答"为什么 LLM-A 选了 X 而不是 Y"得翻 workflow.log 大段日志。decisions.json 把每个决策点拍照,带 reasoning,**直接成为后续 SEA-CDM `analysis` 行的来源数据**(后来确实如此 — 见 2026-05-27)。

### 4. limma 路线决定(deferred work,recorded in README §B)

讨论结果:对 DESeq2 跑不了的研究(FPKM/TPM/log_transformed 矩阵),用 **limma-trend**(moderated t + eBayes on log2(x+1))。

- 选 limma 不选普通 t-test 的理由:**小样本** RNA-seq 研究普遍存在,limma 的经验贝叶斯方差缩约能极大降低 false positive
- batch 将按矩阵类型分支:raw → DESeq2,FPKM/TPM/log → limma
- 下游 GSEA/ORA 复用不变
- **故意延后**:在 Agent A 暴露非 raw 数据真实出现频率之前不做(YAGNI)。后续 2026-05-27 真做了
